## What

The adopter and AI guide, the architecture diagram, the changelog, and a CI workflow with no
install step. The release gate is seven commands — inventory, fidelity, policy, diagrams, test,
audit, validate — all exiting 0 with a `COMPLIANT` verdict.

## Why

The pack asks other projects to publish their coverage honestly. It has to do so first.

## Notes

`README.md` publishes the split from day one: 29 rules, 22 machine-evaluated at mostly partial
assurance, 7 manual-review. And the sentence that matters most — **`COMPLIANT` means everything
checked passed, never everything was checked.** `frameworkCoverage` ships beside the verdict and
never inside it, so a coverage improvement can never be mistaken for a compliance improvement.

`INSTRUCTIONS.md` carries a "Current limitations" table with more honest rows than a marketing
document would allow: content adequacy is not machine-checked, fabrication detection is human-only,
citation validity is manual, and the invariant's protection has stated limits.

The zero-dependency constraint is structural rather than a preference. CI has no install step,
which is what lets the diagram check exist at all — it compares text, not pictures, because a check
needing a headless browser would not run here and the rule would go unenforced.

This documentation was not perfect on release. `v1.0.1` (`b914efc`) exists because the adopter guide
described the pinning mechanism incorrectly, which the first real adoption would have hit.
