## What

Change `detectMode` in `scripts/init.mjs` so that a repository containing shipped work is not
classified `greenfield`, whatever the depth of its implementation markers.

## Why

This is proposal 0004's release objective and the reason its decision moved to `build`.

## Notes

**Scope constraint, and it is the load-bearing part of this story.** The prompt-marker branch is out
of scope. If a repository still ends up in `EXISTING_WITH_PROPOSALS` because it holds
`artifacts/prompts/` and no proposals, leave it there — that outcome belongs to proposal 0006 and
must stay visible until 0006 is decided. Choosing among 0006's remap, drop, or report alternatives
inside this story would answer an open proposal by implementation, which is the failure both
documents were separated to prevent.

The two success criteria in 0004 must both hold, and the first must be shown failing against the
current implementation before the change lands: markers below the root do not read as `greenfield`,
and a genuinely empty directory still does. A fix in one direction only makes the `greenfield` mode
unreachable, which trades one wrong answer for another.

Whatever is concluded, the reported evidence must still say what the tool saw and mark the judgement
`INFERRED`. A guess that cannot be told from a certainty is the failure mode this whole area exists
to avoid.

Two kill criteria from 0004 still apply while this is being written: any third-party dependency stops
the work, and so does detection costing more than a full `standards validate`. The recorded
measurements say neither is close, but they were measured on candidates, not on the implementation.
